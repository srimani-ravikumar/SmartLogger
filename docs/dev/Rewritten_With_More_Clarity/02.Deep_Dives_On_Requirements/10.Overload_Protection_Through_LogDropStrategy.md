## Framework should protect the application during high logging volume

* Log messages should be processed using an internal queue.
* The maximum queue size should be configurable.
* When the queue reaches its configured capacity, a configurable log drop strategy should be applied.

## Framework should support multiple log drop strategies

* Drop low-priority log messages first (Debug, Info).
* Sample log messages instead of logging every message.
* Always retain Error and Fatal log messages.

## Framework should provide visibility into dropped log messages

* The framework should track the total number of dropped log messages.
* Dropped log statistics should be exposed for monitoring and troubleshooting.

### Design

The overload protection mechanism follows a simple workflow:

```text
Application Threads
        │
        ▼
   Internal Queue
        │
        ▼
 Is Queue Full?
    │        │
   No       Yes
    │        │
    ▼        ▼
 Process   Apply Log Drop Strategy
    │        │
    └────┬───┘
         ▼
    Background Worker
         │
         ▼
      Appender
```

The design ensures that excessive logging does not impact application performance while preserving the most important log messages.
