# Future Enhancements

## 1. Move from Correlation ID → Structured Log Context

Currently, the logger supports a single `CorrelationId` to group logs per request:

```text
CorrelationId = "123"
```

This solves basic traceability, but real-world systems require richer context:

```text
CorrelationId = 123
UserId        = 42
TenantId      = "india"
FeatureFlag   = "new-checkout"
```

A single correlation ID answers:

* Which request is this?

But production systems also need:

* Who triggered this?
* Which tenant is involved?
* Which feature or flow is active?
* Which job or background process is running?

### Expected Direction

Introduce a **key-value based ambient context** (log enrichment):

```text
LogContext = {
  CorrelationId: "123",
  UserId: "42",
  Tenant: "IN",
  RequestPath: "/checkout"
}
```

> Instead of a single tag, every log carries a ***small metadata bag.***
