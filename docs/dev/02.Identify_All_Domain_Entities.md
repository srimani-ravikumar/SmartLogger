# Core Entities Documentation

## LogLevel

Represents the severity of a log message.

* Defined as an enum: `DEBUG`, `INFO`, `WARNING`, `ERROR`, `FATAL`
* Ordered by priority (low → high)
* Used for filtering logs based on minimum threshold

### Behavior

* `IsGreaterOrEqual(LogLevel threshold)`

  * Returns true if the current level meets or exceeds the given threshold
  * Used to decide whether a log should be processed

---

## LogMessage

Represents a single log entry with all required metadata.

### Fields

* `Timestamp`
  Time (UTC) when the log is created

* `LogLevel`
  Severity of the log

* `Message`
  Actual log content

* `Source`
  Logical origin of the log (typically class or component name)

* `ThreadId`
  Thread that generated the log

* `CorrelationId`
  Optional identifier used to group logs belonging to the same execution flow

---

### Construction

Uses a builder pattern to ensure correctness and consistency.

* `LogLevel` is mandatory
* `Message` is mandatory
* `Timestamp` and `ThreadId` are assigned automatically

This prevents partially constructed or invalid log messages.

---

## LogConfigurationHolder

Represents the complete logging configuration.

### Fields

* `RootLogLevel`
  Default log level applied when no specific override is defined

* `LoggerOverrides`
  Dictionary mapping logger name → log level
  Allows fine-grained control per component

* `Appenders`
  Collection of output configurations defining where logs are written

---

### Behavior

* If no appenders are configured:

  * Console logging is automatically enabled
  * Ensures logs are not silently lost

---

## AppenderConfiguration

Defines how logs are written to a specific destination.

### Fields

* `Destination`
  Target output type (Console, FileSystem, DatabaseSystem)

* `Threshold`
  Minimum log level required for this appender to process a message

* `Settings`
  Key-value configuration specific to the destination
  Examples: file path, connection string

---

## LogOutputDestination

Defines supported log output types.

* `Console` → writes to standard output
* `FileSystem` → writes to files
* `DatabaseSystem` → reserved for future support

---

## LogContext

Provides execution-scoped context for logging.

### Purpose

Allows attaching a correlation identifier to all logs within a logical operation (such as a request or job) without passing it explicitly.

---

### Key Characteristics

* Uses `AsyncLocal` to store context
* Flows automatically across async calls
* Is isolated per execution flow
* Not tied to any specific logger instance

---

### API

* `CorrelationId`
  Returns the current correlation identifier, if set

* `BeginCorrelationScope(string correlationId)`
  Starts a scoped context

---

### Behavior

* All logs created within a scope automatically include the correlation ID
* Previous context is restored when the scope ends
* Supports nested scopes safely

---

### Usage

```csharp
using (LogContext.BeginCorrelationScope("123"))
{
    logger.Info("Processing request");
}
```

---

## Design Summary

* LogMessage captures the data
* LogLevel controls filtering
* Configuration controls behavior
* LogContext provides execution-level metadata

The system is designed to be:

* predictable (no hidden state changes)
* extensible (new destinations and metadata can be added)
* safe for concurrent and asynchronous execution
* decoupled (logging and context are independent concerns)
