# SmartLogger - Package Structuring

## Core Package
**Purpose**: Central logging orchestration and interfaces defining the framework's contracts.

**Key Responsibilities**:
- Define logging operations via `ISmartLogger`
- Manage logger lifecycle through `LoggerFactory` and `LoggerManager`
- Represent log entries with structured `LogMessage` objects
- Define severity levels with `LogLevel` enumeration
- Provide configuration holder for centralized settings
- Enable correlation tracking via `LogContext`

**Key Interfaces**:
- `ISmartLogger`: Primary contract for logging operations
- `ILogAppender`: Contract for output destinations
- `ILogConfigurationProvider`: Contract for configuration loading
- `ILogFilter`: Contract for message filtering
- `ILogLayoutStrategy`: Contract for layout rendering
- `ILogOutputFormatterStrategy`: Contract for output formatting
- `ITokenRendererStrategy`: Contract for token substitution

---

## Appenders Package
**Purpose**: Define output destinations and their configurations.

**Key Responsibilities**:
- Route log messages to console
- Route log messages to files
- Apply log level thresholds per appender
- Format messages before output
- Support multiple output formats (PlainText, JSON, XML)

**Key Classes**:
- `ConsoleAppender`: Routes logs to stdout/stderr
- `FileAppender`: Routes logs to file system
- `AppenderConfiguration`: Holds appender settings

---

## FileRolling Subpackage
**Purpose**: Manage file rotation strategies for log files.

**Key Responsibilities**:
- Detect when a log file should be rolled/rotated
- Generate new file paths during rotation
- Support multiple rolling strategies (Size-based, Time-based)

**Key Interfaces**:
- `IRollingStrategy`: Contract for rolling behavior
- Implementations: `SizeRollingStrategy`, `TimeRollingStrategy`

---

## Configurations Package
**Purpose**: Load and manage logging configuration from various sources.

**Key Responsibilities**:
- Load configuration from JSON files with auto-reload capability
- Load configuration from in-memory sources
- Validate configuration during load
- Provide configuration to the logging framework

**Key Classes**:
- `JsonConfigurationProvider`: Loads from JSON with file watching
- `InMemoryConfigurationProvider`: Loads from memory

---

## Formatters Package
**Purpose**: Transform log messages into different output formats.

**Key Responsibilities**:
- Format messages as plain text with layouts
- Format messages as JSON with field selection
- Format messages as XML
- Create appropriate formatter instances

**Key Classes**:
- `PlainTextFormatter`: Renders plain text using layout strategy
- `JsonFormatter`: Serializes logs as JSON objects
- `XmlFormatter`: Serializes logs as XML elements
- `FormatterFactory`: Creates formatters based on configuration

---

## LogLayouts Subpackage
**Purpose**: Support pattern-based layout rendering for plain text logs.

**Key Responsibilities**:
- Parse log patterns with token placeholders
- Render patterns with actual values from log messages
- Support extensible token system

**Key Classes**:
- `PatternLayout`: Renders patterns by substituting tokens
- `LayoutFactory`: Creates layout instances

---

## Tokens Subpackage
**Purpose**: Define tokens that can be substituted in log patterns.

**Key Responsibilities**:
- Provide token symbols (e.g., `%timestamp%`, `%level%`)
- Render token values from log context
- Support extensible token registration

**Key Classes**:
- `TokenRegistry`: Central registry of available tokens
- Token Implementations: `TimestampToken`, `LevelToken`, `MessageToken`, `SourceToken`, `ThreadToken`, `CorrelationToken`

---

## Filters Package
**Purpose**: Implement message filtering strategies.

**Key Responsibilities**:
- Filter logs based on severity level
- Evaluate whether a message should be processed
- Support extensible filter implementations

**Key Classes**:
- `LevelFilter`: Filters logs by minimum severity level

---
