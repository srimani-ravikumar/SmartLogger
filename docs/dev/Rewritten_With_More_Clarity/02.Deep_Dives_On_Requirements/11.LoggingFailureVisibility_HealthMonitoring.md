## Framework should provide visibility into its own health

* Track failures for each output destination.
* Track dropped log messages due to overload.
* Track the last successful write time for each output destination.

## Framework should expose logging health events

* Provide hooks or callbacks for sink failure events.
* Provide hooks or callbacks for repeated logging failures.
* Provide hooks or callbacks when the logging pipeline is degraded.

## Framework should help applications detect logging failures

* Applications should be able to detect when logging is not functioning correctly.
* Health information should be available for monitoring, diagnostics, and alerting.

### Design

The logging health monitoring follows a simple workflow:

```text id="uj83po"
Application
      │
      ▼
    Logger
      │
      ▼
   Appender
      │
      ├───────────────┐
      │               │
Success            Failure
      │               │
      ▼               ▼
 Update Last      Record Failure
 Success Time          │
      │                ▼
      │         Update Health Metrics
      │                │
      └────────┬───────┘
               ▼
      Health Monitor
               │
               ▼
      Hooks / Callbacks
               │
               ▼
      Monitoring System
```

The design ensures that logging failures are visible to the application, allowing developers and operators to detect, diagnose, and respond to logging issues without affecting the application's execution.
